# URL Structure Improvement Plan
**Goal: Get individual coloring pages indexed by Google**
**Status: Planning — not yet implemented**

---

## 1. Root Cause Diagnosis

### What Google sees today
Running `site:magicpencil.fun` returns 2 pages: the homepage and one blog post.
All 90 coloring pages and all 12 category pages return "URL is unknown to Google."

### Why — three compounding problems

| Problem | Evidence |
|---|---|
| Wrong canonical on `coloring.html` | Static `<link rel="canonical" href="https://magicpencil.fun/coloring.html">` with no `?image=` — every coloring page tells Google it is a duplicate of the bare shell |
| Zero readable HTML content | `coloring.html` has no `<h1>`, no description text — just a JS app shell. Google won't index a page with no content |
| Query-param URLs for category pages | `category.html?cat=animals` canonical is set by JS, which Google may read too late |

The canonical bug is the primary blocker. Even if we fix content, the broken canonical actively suppresses all 90 URLs. Both must be fixed together.

---

## 2. Target Architecture

### New URL structure

| Page type | Old URL | New URL |
|---|---|---|
| Category | `category.html?cat=animals` | `categories/animals.html` |
| Coloring (desktop) | `coloring.html?image=animals-elephant` | `color/animals/elephant.html` |
| Coloring (mobile) | `coloring-mobile.html?image=animals-elephant` | stays as-is (see §5) |

### Design principle
Each generated HTML file contains only what makes it unique (title, canonical, h1, blurb). The coloring engine, color palette, and all tool logic live in **shared JS files** that are not touched per-image. Future changes to the tool require editing one file, not 90.

```
color/animals/elephant.html     ← unique: title, canonical, h1, blurb, data-image-id
color/animals/lion.html         ← unique: title, canonical, h1, blurb, data-image-id
                                      ↓ all load the same:
js/coloring.js                  ← shared coloring engine (unchanged logic)
js/data/image-catalog.js        ← shared catalog (auto-generated)
css/main.css                    ← shared styles
```

## 4. Files to Create

### 4.1 `scripts/tools/generate-pages.py` (new script)

**What it does:**
1. Reads `js/data/image-catalog.js` (parses the JS array with regex, same pattern as `generate-sitemap.py`)
2. Reads `scripts/tools/page-content.json` if it exists (optional manual overrides for titles/blurbs)
3. Generates `color/[category]/[slug].html` for every image
4. Generates `categories/[cat].html` for every category
5. Auto-generates SEO content from image name when no override exists

**Slug generation rule:**
- Image ID: `animals-elephant` → category: `animals`, slug: `elephant`
- Image ID: `animals-honey-bee` → category: `animals`, slug: `honey-bee`
- Rule: strip the `{category}-` prefix from the ID to get the slug

**Auto-generated content template (per image):**
```
title:       "{Name} Coloring Page for Kids — Free Online | MagicPencil"
description: "Color a {name} online for free! Tap to fill with colors, gradients, and patterns. Perfect for kids ages 2–12. Print or download your artwork."
h1:          "{Name} Coloring Page"
blurb:       "Bring this {name} to life with your favorite colors! Tap any area to fill it instantly. Try solid colors, rainbow gradients, or fun patterns like dots and stars. When you're done, download your artwork or print it out."
```

**Auto-generated content template (per category):**
Uses content already in `js/data/category-metadata.js` — the `contentDescription` field is already rich HTML. The script extracts it and injects it into the category template.

**`page-content.json` format** (for custom overrides):
```json
{
  "animals-elephant": {
    "title": "Elephant Coloring Page for Kids — Free Online | MagicPencil",
    "description": "Color a friendly elephant online for free!",
    "h1": "Elephant Coloring Page",
    "blurb": "Elephants are the largest land animals on Earth! Did you know they can use their trunks to pick up objects as small as a coin? Color this elephant gray, or go wild with any colors you like."
  }
}
```

### 4.2 `scripts/tools/templates/page-desktop.html`

The single HTML template for all generated coloring pages. Contains `{{PLACEHOLDER}}` tokens that `generate-pages.py` replaces.

**Key placeholders:**
```
{{TITLE}}           → "Elephant Coloring Page for Kids | MagicPencil"
{{DESCRIPTION}}     → meta description content
{{CANONICAL}}       → "https://magicpencil.fun/color/animals/elephant.html"
{{H1}}              → "Elephant Coloring Page"
{{BLURB}}           → 2–3 sentence description paragraph
{{IMAGE_ID}}        → "animals-elephant" (used as data attribute)
{{CATEGORY}}        → "animals"
{{CATEGORY_NAME}}   → "Animals"
{{CATEGORY_URL}}    → "/categories/animals.html"
{{BREADCRUMB_JSON}} → JSON-LD breadcrumb schema
{{IMAGE_SCHEMA_JSON}}→ JSON-LD ImageObject schema
```

**Critical: all paths must be absolute (leading `/`)**
This template is served from `/color/[category]/[slug].html` — two directory levels deep. Any relative path (`css/main.css`, `images/...`) will resolve against `/color/[category]/` and 404. Every CSS, JS, image, and navigation href must use an absolute path.

**Template body structure:**
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <title>{{TITLE}}</title>
  <meta name="description" content="{{DESCRIPTION}}">
  <link rel="canonical" href="{{CANONICAL}}">
  <!-- favicons: all /assets/... paths (absolute) -->
  <!-- Open Graph tags -->
  <!-- CSS: MUST use absolute paths — coloring.html uses relative paths, do NOT copy them as-is -->
  <link rel="stylesheet" href="/css/main.css">
  <link rel="stylesheet" href="/css/responsive.css">
  <link rel="stylesheet" href="/css/coloring-page.css">
  <link rel="stylesheet" href="/css/cookie-consent.css">
  <!-- NO mobile-redirect.js here — it goes before </body> (see below) -->
</head>
<body class="coloring-page">

  <!-- SEO content: visible to Google, above the fold -->
  <nav class="breadcrumb">
    <a href="/">Home</a> › <a href="{{CATEGORY_URL}}">{{CATEGORY_NAME}}</a> › {{H1}}
  </nav>
  <h1>{{H1}}</h1>
  <p class="page-blurb">{{BLURB}}</p>

  <!-- coloring tool: the engine reads image from data attribute, not URL -->
  <div id="coloring-app" data-image-id="{{IMAGE_ID}}" data-category="{{CATEGORY}}">
    <!-- header, panels, canvas — copied from coloring.html; all nav hrefs must be absolute -->
    <!-- e.g. href="/index.html" not href="index.html" -->
  </div>

  <!-- shared scripts (all absolute paths) -->
  <script src="/js/data/image-catalog.js"></script>
  <script src="/js/data/category-metadata.js"></script>
  <script src="/js/colors.js"></script>
  <script src="/js/coloring.js"></script>
  <script src="/js/ui.js"></script>
  <script src="/js/download.js"></script>
  <script src="/js/app.js"></script>
  <script src="/js/cookie-consent.js"></script>

  <!-- Mobile redirect MUST be last — needs #coloring-app in DOM to read data-image-id -->
  <script src="/js/mobile-redirect.js"></script>
</body>
```

### 4.3 `scripts/tools/templates/page-category.html`

Template for category pages (`categories/animals.html`).

**Key placeholders:**
```
{{TITLE}}              → from category-metadata.js title field
{{DESCRIPTION}}        → from category-metadata.js description field
{{CANONICAL}}          → "https://magicpencil.fun/categories/animals.html"
{{CATEGORY_ID}}        → "animals"
{{CATEGORY_NAME}}      → "Animals"
{{CONTENT_DESCRIPTION}}→ full HTML from category-metadata.js contentDescription
```

The image grid is still rendered by JS (reads from `image-catalog.js`), but the title, h1, and content description are baked into the static HTML. This is enough for Google to distinguish each category page.

**Critical: expose category ID for JS.** `initializeCategoryPage()` in `app.js` currently reads the category from `?cat=` URL param. On `/categories/animals.html` there is no query string — if the data attribute is missing, the function will redirect to the homepage. The template must store the category ID where JS can read it:

```html
<body class="category-page" data-category-id="{{CATEGORY_ID}}">
```

### 4.4 Legacy URL preservation (no `_redirects` needed)

Netlify `_redirects` **cannot match query parameters** in the `from` field — `:splat` captures path segments, not query strings. A rule like `/coloring.html /color/:splat 200` would only match requests to the bare `coloring.html` path (no query string) and break it.

**Do not create a `_redirects` file for old coloring/category URLs.**

Instead, keep both legacy files alive as-is:
- `coloring.html` — still works for old bookmarks (e.g. `coloring.html?image=animals-elephant`)
- `category.html` — still works for old bookmarks (e.g. `category.html?cat=animals`)

The new clean URLs (`/color/...`, `/categories/...`) are what Google indexes going forward. Legacy files are a UX safety net, not an SEO concern. A proper redirect from old query-param URLs to clean URLs would require a Netlify Edge Function — defer this indefinitely; it's not required for indexing.

## 5. Mobile Strategy

### Current flow
```
coloring.html?image=X  →  (if mobile) coloring-mobile.html?image=X
```

### New flow
```
color/animals/elephant.html  →  (if mobile) coloring-mobile.html?image=animals-elephant
```

### How it works
The generated desktop page has `data-image-id="animals-elephant"` on the `#coloring-app` container. The updated `mobile-redirect.js` reads this attribute to construct the redirect URL:

```js
// Updated mobile-redirect.js
// NOTE: This script must be placed just before </body> in generated pages (not in <head>).
// Reason: generated pages carry data-image-id on #coloring-app in the body.
// In coloring.html (legacy), it can stay in <head> because it reads ?image= from the URL.
(function () {
    var isMobile = window.matchMedia('(max-width: 767px)').matches
                || /Android|iPhone|iPad|iPod/i.test(navigator.userAgent);
    if (!isMobile) return;
    if (window.location.pathname.indexOf('coloring-mobile') !== -1) return;

    // Legacy: old ?image= URL (coloring.html)
    var legacyParam = new URLSearchParams(window.location.search).get('image');
    if (legacyParam) {
        window.location.replace('/coloring-mobile.html?image=' + legacyParam);
        return;
    }

    // New: generated page — script is at end of body so DOM is already available, no event needed
    var app = document.getElementById('coloring-app');
    if (app && app.dataset.imageId) {
        window.location.replace('/coloring-mobile.html?image=' + app.dataset.imageId);
    }
})();
```

### Mobile canonical
`coloring-mobile.html` currently has a hardcoded wrong canonical. It must be updated to point to the desktop clean URL for whichever image is loaded:

```js
// In coloring-mobile.html or coloring-mobile.js init:
// After reading ?image=animals-elephant from URL:
const imageId = new URLSearchParams(window.location.search).get('image');
if (imageId) {
    const image = getImageById(imageId);
    if (image) {
        const slug = imageId.replace(image.category + '-', '');
        const cleanUrl = `https://magicpencil.fun/color/${image.category}/${slug}.html`;
        document.getElementById('canonical-tag').href = cleanUrl;
    }
}
```

This tells Google: "the canonical version of this mobile page is the desktop clean URL." So mobile pages are never independently indexed — they piggyback on the desktop URLs.

## 8. Content Requirements for SEO

For Google to index and rank individual pages, each page needs at minimum:
- Unique `<title>` (60–70 chars) — **baked into static HTML**
- Unique `<meta name="description">` (150–160 chars) — **baked into static HTML**
- Unique `<link rel="canonical">` pointing to itself — **baked into static HTML**
- One `<h1>` matching the image name — **baked into static HTML**
- One `<p>` blurb of 40–80 words — **baked into static HTML**

Auto-generated content is acceptable for launch. Manually written blurbs for the top 20 most-searched images (elephant, lion, unicorn, dinosaur, butterfly, etc.) will improve ranking speed for those terms.
